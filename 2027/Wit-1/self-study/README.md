学习方式是先跑通例子，再读关键代码，改参数验证自己的理解。环境配置、示例代码和自动验证由 AI 协助准备，笔记也根据学习过程整理，不把运行过示例等同于已经能独立开发完整系统。

## 后续学习方向

1. 继续 ROS 工程学习：通信与 TF 排错、YAML 配置、rosbag 播放控制与仿真时间、构建依赖与安装空间。
2. OpenCV：图像读写、颜色空间、阈值、轮廓、灯条筛选和装甲板配对。
3. 相机与空间解算：标定、畸变、内外参、PnP，以及相机到机器人坐标系的转换。
4. 神经网络：区分训练和推理，跑通现成模型，分析预处理、置信度、误检漏检和耗时。
5. 跟踪：卡尔曼滤波的预测与校正、噪声、数据关联和目标丢失；按需补矩阵、概率和 Eigen。
6. 对照战队项目，把相机、检测、解算、跟踪和输出串起来，记录复现过程与自己的理解。

按知识之间的依赖推进，不安排固定的每日时间表。

## AI 协助与自己需要做的事

| 内容 | 学习时的分工 |
| --- | --- |
| 配置环境、创建包、准备构建文件和示例 | 可以由 AI 协助完成，自己理解用途和关键路径 |
| 解释代码、整理命令、编写检查脚本 | 可以用 AI 辅助，但要对照实际运行结果判断 |
| 改速度、目标位置和话题连接 | 自己先预测结果，再运行、观察并解释变化 |
| 遇到错误 | 保留现象和报错，学会定位问题属于环境、连接、类型还是程序逻辑 |
| 后续接触硬件与视觉 | 相机安装、采集标定图像、检查真实效果等需要实际操作，AI 可辅助分析和处理数据 |

目前不是要求把所有脚手架代码手写一遍，而是先读懂关键逻辑，能解释输入、输出和实验结果，再逐步练习独立实现。

## 如何看这些记录

每篇围绕“概念 → 实验 → 观察与解释”整理。命令中的预期输出用于核对行为，不代表所有数值都必须逐位一致。自动验证结果与我在交互式学习中确认的理解分别说明。

示例包的源码只保留一份，放在 [ros1/turtle_control](ros1/turtle_control)。本机开发工作空间通过链接和 Docker 挂载使用这份源码，构建结果、运行日志和缓存放在学习仓库之外。其他 ROS 1 Noetic 环境中的复现方法见示例包 README。
